Это инструкция для тех, кто смотрит прогноз и правит тексты новостей.  
Здесь описано, **где что лежит** и **что происходит по нажатию**.

> **Важно.** Прогноз приходит из [Open-Meteo](https://open-meteo.com/) и хранится в Valkey **30 дней**. Если записи больше **10 минут**, страница запрашивает API снова. Если API не ответил, на экране остаётся сохранённый прогноз. Отдельной админки у проекта нет.

## Как открыть

**Сайт** — прогноз и новости. Локально он открывается по адресу из **`DEFAULT_URI`** в `.env` (в примере — `http://weatherman.docker.local`) или по `http://localhost`, порт **80**.

Имя **`weatherman.docker.local`** нужно прописать в `/etc/hosts`:

```text
127.0.0.1 weatherman.docker.local
```

**Главная** сразу открывает прогноз для **Санкт-Петербурга**. Москва живёт по адресу `/?city=moskva`.

**Новости** — список материалов. Адрес: `/news`.

Вход, пароль и личный кабинет не используются.

## Прогноз

### Шапка

| Элемент | Что произойдёт |
| --- | --- |
| Логотип | Открывает прогноз. Для Москвы сохраняет `?city=moskva`. |
| **Прогноз** | Тоже открывает прогноз выбранного города. Пункт подсвечен на главной. |
| **Новости погоды** | Открывает `/news`. |
| **Сейчас**, **По часам**, **На 10 дней** | Прокручивают страницу к соответствующему блоку. |
| Город | Открывает список: Санкт-Петербург и Москва. Повторное нажатие, щелчок мимо списка или клавиша **Esc** его закрывают. |
| Переключатель темы | Меняет светлую тему на тёмную и обратно. Выбор запоминается в браузере. |
| Кнопка меню | Появляется, когда пункты шапки не помещаются в одну строку. Открывает те же пункты столбиком. |

На широком экране **Прогноз** и **Новости погоды** стоят слева, сразу за логотипом. Якоря, город и тема стоят справа.

### Сейчас

Крупная температура, строка «Ощущается как…», сравнение со вчерашним часом, если оно есть, и название условия. Под ними — факты в плитках. Ниже — короткий текст по частям ближайших суток.

### По часам и на 10 дней

**Почасовой прогноз** листается вбок. У часа есть температура и, если осадки вероятны, процент. Восход и закат стоят в той же ленте.

**Прогноз на 10 дней** начинается с полоски. Нажатие на день раскрывает карточку ниже. В карточке — части суток: погода, ощущение, ветер, влажность и давление. Там же восход, закат, световой день, ультрафиолет и фаза Луны. Первая карточка открыта сразу.

Фаза Луны считается в проекте по дате. Остальные числа приходят из Open-Meteo.

### Подвал

Внизу страницы прогноза указан источник и координаты города. Под всеми страницами, включая новости и **404**, есть отдельная плашка: **@grobolof** ведёт на страницу разработчика, **исходным кодом** — на репозиторий проекта. Обе ссылки открываются в новой вкладке.

## Новости

Список собирается из таблицы `news`. На экране двадцать карточек. Если материалов больше, внизу есть **Показать ещё**: следующая порция дописывается без перезагрузки страницы. Без JavaScript та же ссылка открывает следующую порцию обычным переходом.

| Что сделали | Что произойдёт |
| --- | --- |
| Нажали **Сначала новые** или **Сначала старые** | Список перестраивается. Адрес получает `sort=desc` или `sort=asc`. |
| Нажали карточку | Открывается материал: обложка, дата, текст абзацами. |
| У материала несколько снимков | Под текстом галерея. Стрелки и точки листают кадры. |
| Снимков нет | Галереи на странице нет. |
| Номера в адресе нет | Страница **404**. |

Сортировка и порции читают одну и ту же таблицу. Отдельного черновика у новости нет: что лежит в базе, то видно на сайте.

## Откуда берётся прогноз

1. Браузер открывает `/` или `/?city=moskva`.
2. Сервер смотрит Valkey. Ключ зависит от координат и набора полей Open-Meteo.
3. Если запись моложе 10 минут, страница собирается из неё. Повторный запрос к API не уходит.
4. Если записи нет или ей больше 10 минут, сервер запрашивает `https://api.open-meteo.com/v1/forecast`. Удачный ответ записывается в Valkey на 30 дней и сразу показывается.
5. Если API ответил ошибкой, а в Valkey ещё есть запись младше 30 дней, страница показывает её.
6. Если API не ответил и сохранённой записи нет, вместо прогноза открывается «Прогноз временно недоступен».

Ветер в запросе просится в метрах в секунду. Часовой пояс города — `Europe/Moscow`.

Новости в Valkey не пишутся. Они читаются из PostgreSQL.

## Запуск

Нужны Docker и файл `.env` в корне репозитория. Его собирают из `.env.example`.

В `/etc/hosts` добавляют строку `127.0.0.1 weatherman.docker.local`, затем:

```bash
make up
make migrations-up
make console CMD="doctrine:fixtures:load --no-interaction"
```

`make up` поднимает контейнеры. `make migrations-up` создаёт таблицу новостей. Команда с фикстурами заполняет её демо-материалами и заново записывает таблицу.

| Сервис | Зачем | Порт на компьютере |
| --- | --- | --- |
| **application** | Symfony на PHP 8.5. Корень репозитория смонтирован в контейнер. | **80** |
| **database** | PostgreSQL 18. В ней лежат новости. | **5432** |
| **valkey** | Кэш ответа Open-Meteo. Данные лежат в томе и переживают перезапуск контейнера. | **6379** |
| **mailpit** | Перехват почты, если он включён. Сайт письма не отправляет. | **8025**, **1025** |

Остановить контейнеры: `make stop`.  
`make down` удаляет контейнеры и том Valkey.

Пока контейнеры запущены:

```bash
make console CMD="debug:router"
make cache-clear
make test
```

`make console` выполняет команду Symfony внутри контейнера приложения.

Код экранов лежит в `templates`, стили — в `public/styles/weather.css`. Запрос прогноза и правила кэша — в `src/Weather/OpenMeteoClient.php`. Сборка страницы из ответа API — в `src/Weather/ForecastAssembler.php`. Новости — в `src/Controller/NewsController.php` и `src/Repository/NewsRepository.php`.

### Переменные `.env`

| Переменная | Зачем |
| --- | --- |
| **`APP_HOST`** | Имя сайта для PHP, в примере `weatherman.docker.local`. |
| **`APP_PATH`** | Куда внутри контейнера смонтирован репозиторий. |
| **`DB_CONNECTION`**, **`DB_HOST`**, **`DB_PORT`**, **`DB_DATABASE`**, **`DB_USERNAME`**, **`DB_PASSWORD`** | Доступ к PostgreSQL. В примере хост — `database`, порт — **5432**. |
| **`DATABASE_URL`** | Та же база одной строкой для Doctrine. |
| **`VALKEY_URL`** | Адрес кэша прогноза. В примере `valkey://valkey:6379`. |
| **`DEFAULT_URI`** | Адрес сайта для ссылок вне браузерного запроса. |
| **`SYMFONY_CRON_ENABLED`** | **`1`** — планировщик Symfony запускается раз в минуту. **`0`** — не запускается. На прогноз и новости это не влияет. |
| **`MAILPIT_ENABLED`** | **`1`** — письма уходят в Mailpit. **`0`** — не уходят. Сайт почту не шлёт. |
| **`MAILER_DSN`** | Куда отправлять почту. В примере почта выключена. |

Пароли из `.env` в инструкцию сверх примера не копируйте: боевые значения хранятся только на сервере.

## Частые вопросы

**Где поменять текст новости?**  
В базе, таблица `news`: название, дата, описание, обложка и список снимков. После правки обновите страницу. Демо-тексты лежат в `src/DataFixtures/NewsCatalog.php` и попадают в базу командой `doctrine:fixtures:load`.

**Как добавить город?**  
Сейчас в шапке два города, они описаны в `src/Weather/Place.php`. Новый город — это ещё одна запись там: имя, координаты и часовой пояс. Отдельного списка в конфиге нет.

**Почему на новостях пункты шапки слева, а не справа?**  
**Прогноз** и **Новости погоды** на всех страницах стоят рядом с логотипом. Справа остаётся переключатель темы, а на прогнозе ещё якоря и город.

**Почему на телефоне вместо пунктов кнопка?**  
Если строка шапки не вмещает пункты, они собираются в меню. Логотип остаётся. Нажатие на пункт закрывает меню и открывает страницу или прокручивает прогноз.

**Почему прогноз не изменился сразу после обновления на Open-Meteo?**  
Запись моложе 10 минут отдаётся как есть. Следующий запрос после этого срока сходит в API и перезапишет кэш. Сам кэш живёт 30 дней.

**Почему сайт показывает вчерашние цифры, хотя API сейчас недоступен?**  
Так и задумано. Если свежий запрос не удался, страница берёт последнюю успешную запись из Valkey, пока ей меньше 30 дней.

**Почему вместо прогноза написано «Прогноз временно недоступен»?**  
API не ответил, и в Valkey нет записи. Обновите страницу, когда Open-Meteo снова отвечает.

**Куда пропала новость?**  
Её нет в базе или номер в адресе не совпал. Чужой номер открывает **404**.

**Где лежит исходный код?**  
В репозитории [grobolof/demo-weatherman](https://github.com/grobolof/demo-weatherman). Ссылка есть на плашке внизу каждой страницы. Страница разработчика — [github.com/grobolof](https://github.com/grobolof).
